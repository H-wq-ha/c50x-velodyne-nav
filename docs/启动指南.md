# 环境与启动指南

核对日期：**2026-11-12**。以下命令依据本副本源码整理，未在本次执行。示例使用仓库当前路径和显式参数，避免读取原机器的模型 / 地图目录。当前副本的地图、构建产物、虚拟环境和日志已清理。

所有命令中的 `LIDAR_WS` 指向本仓库根目录；相机序列号、串口和蓝牙地址使用自己的设备值。不同启动场景分开运行，避免重复打开相机、串口、雷达 UDP 端口或重复发布安装 TF。

## 1. 环境准备

### ROS 依赖和主工作区

基础环境为 Ubuntu 22.04、ROS 2 Humble、系统 Python 3.10，预先安装 rosdep 和 colcon。串口用户需要设备访问权限，上位机需与 VLP-16 处于可通信网段；历史硬件配置使用雷达 `192.168.1.201`、UDP 2368、串口 460800 baud。

在仓库根目录执行：

```bash
export LIDAR_WS="$(pwd -P)"
source /opt/ros/humble/setup.bash
rosdep install --from-paths src --ignore-src --rosdistro humble -y
colcon build --symlink-install \
  --packages-select car_bringup velodyne_bringup semantic_mapping
source "$LIDAR_WS/install/setup.bash"
```

包清单覆盖 Velodyne、RTAB-Map、Nav2、Madgwick、RealSense ROS 驱动等运行依赖。RealSense 还需要可工作的底层 SDK / USB 访问环境；Python 语义依赖按下一节补齐。这里仅构建 `src/` 下的主链，标定系统单独构建。

### 语义推理依赖

ROS 节点使用 `/usr/bin/python3`。在仓库外创建可复用系统包的推理环境，避免重新打包虚拟环境：

```bash
sudo apt install python3-venv python3-pip python3-opencv python3-numpy
export LIDAR_AI_ENV="$HOME/.venvs/lidar-ai"
/usr/bin/python3 -m venv --system-site-packages "$LIDAR_AI_ENV"
"$LIDAR_AI_ENV/bin/python" -m pip install \
  'numpy<2' 'onnxruntime>=1.17,<2' pyrealsense2
export LIDAR_AI_SITE="$("$LIDAR_AI_ENV/bin/python" -c 'import sysconfig; print(sysconfig.get_path("purelib"))')"
```

`numpy<2` 用于兼容 Humble 系统 `cv_bridge` 等扩展的 NumPy ABI。不要把 `ImuCalibration/requirements.txt` 中的 NumPy 2 环境注入 ROS 进程。上述命令提供主链的依赖准备方式，仓库没有完整锁定新机器上的全部 Python / SDK 版本。

现存模型为 `yolov8_d435i/models/yolov8n_256.onnx`，另有 320 / 416 / 640 模型。ROS 主链直接使用 ONNX Runtime，不依赖独立实验脚本中的 Torch / Ultralytics 包装层。

### 每个 ROS 终端

在仓库根目录执行；后续章节默认已完成这些步骤：

```bash
export LIDAR_WS="$(pwd -P)"
source /opt/ros/humble/setup.bash
source "$LIDAR_WS/install/setup.bash"
export LIDAR_AI_ENV="$HOME/.venvs/lidar-ai"
export LIDAR_AI_SITE="$("$LIDAR_AI_ENV/bin/python" -c 'import sysconfig; print(sysconfig.get_path("purelib"))')"
```

纯几何 / 底盘功能可以省略最后两项推理环境变量。所有需要互相发现的终端使用相同 `ROS_DOMAIN_ID`。不要混合加载相邻仿真或机械臂工作区的安装环境。

## 2. 一键语义建图

将 `YOUR_D435I_SERIAL` 替换为实际相机序列号：

```bash
ros2 launch semantic_mapping one_click.launch.py \
  serial_no:=YOUR_D435I_SERIAL \
  imu_port:=auto \
  model_path:="$LIDAR_WS/yolov8_d435i/models/yolov8n_256.onnx" \
  python_site_packages:="$LIDAR_AI_SITE" \
  start_rviz:=true
```

入口会先检查模型、相机、依赖和有效底盘 IMU 帧，再启动传感器、TF、ICP、RTAB-Map、三类语义建图和健康监控。底盘仅接收状态帧，不订阅 `/cmd_vel`；需要巡视时由现场另行安排与该只读链兼容的控制方式，不能再启动一个重复占用同一串口的底盘节点。

| 参数 | 源码默认值 / 行为 | 使用建议 |
|---|---|---|
| `serial_no` | 原机器的固定序列号 | 显式传自己的 D435i 序列号 |
| `imu_port` | 原机器的固定设备路径 | 可用 `auto`，也可传实际设备路径 |
| `imu_baudrate` | `460800` | 与固件一致 |
| `model_path` | 未传时读取参数文件中的原机器绝对路径 | 显式传本仓库模型路径 |
| `python_site_packages` | 原机器虚拟环境的绝对路径 | 显式传 `LIDAR_AI_SITE` |
| `map_id` | 空值时生成新 ID | 指定时使用未占用的新名称 |
| `run_root` | `~/.ros/semantic_mapping/runs` | 按需要换到有足够空间的磁盘 |
| `overwrite_databases` | `false` | 保持默认以创建独立会话 |
| `start_rviz` | `false` | 需要图形界面时设为 `true` |
| `use_chassis_imu` | `true` | 设为 false 会同时关闭点云去畸变 |

默认运行目录包含 `rtabmap.db`、`semantic.sqlite3`、`run_identity.json`，健康监控还会生成 `health.json`。它们属于建图会话产物，不自动构成 `maps/latest/` 完整地图包。

## 3. 几何建图与定位导航

### 建立几何地图

无需相机或推理环境。以下入口启用可控底盘节点，默认串口 `/dev/wheeltec_chassis` 写在启动源码中，首次部署需核对或配置该设备别名。

```bash
export LIDAR_GEOMETRY_DB="$HOME/.ros/lidar_geometry/$(date +%Y%m%d_%H%M%S)/rtabmap.db"
mkdir -p "$(dirname "$LIDAR_GEOMETRY_DB")"
ros2 launch velodyne_bringup rtabmap_slam.launch.py \
  database_path:="$LIDAR_GEOMETRY_DB" \
  delete_db:=false
```

显式新目录避免使用旧默认数据库；`rtabmap_slam.launch.py` 的源码默认 `delete_db=true`，示例主动覆盖。另开终端加载同一工作区后启动键盘：

```bash
ros2 run car_bringup keyboard_teleop
```

W/S 前后、A/D 转向、Q/E 调节线速度、空格停止。该传统入口的坐标前向与语义导航入口不同，安装 TF 及实际车辆朝向应按 [TF 专题](雷达相机TF初步关系.md)核对。

### 导出几何地图

建图仍运行时，另一个终端保存二维栅格：

```bash
mkdir -p "$LIDAR_WS/maps"
ros2 run nav2_map_server map_saver_cli \
  -t /map -f "$LIDAR_WS/maps/rtabmap_nav2_latest"
```

结束键盘与建图进程、等待数据库关闭后，在原建图终端备份对应数据库：

```bash
cp "$LIDAR_GEOMETRY_DB" "$LIDAR_WS/maps/rtabmap_nav2_latest.db"
```

现有 `scripts/save_rtabmap_map.sh` 也可导出栅格，但它尝试备份的数据库固定是 `~/.ros/rtabmap.db`，不是上例的新数据库。采用显式数据库路径时，按上述步骤复制同一会话的库，不能把脚本自动找到的另一份库当成配套结果。

### 使用 AMCL 定位和 Nav2

结束建图后，在已加载环境的终端启动：

```bash
ros2 launch velodyne_bringup nav2_bringup.launch.py \
  map:="$LIDAR_WS/maps/rtabmap_nav2_latest.yaml"
```

该入口包含雷达、IMU、ICP、雷达二维扫描投影、AMCL、Nav2 和 RViz。使用 `2D Pose Estimate` 指定初始位置，再用 `Nav2 Goal` 发送目标。底盘控制默认启用。

### 使用 RTAB-Map 定位和 Nav2

为避开旧整合入口中的固定地图路径，可用两个现有入口组合。终端 A 启动 RTAB-Map 定位及传感器：

```bash
ros2 launch velodyne_bringup rtabmap_slam.launch.py \
  localization:=true \
  database_path:="$LIDAR_WS/maps/rtabmap_nav2_latest.db" \
  delete_db:=false \
  start_rtabmap_viz:=false
```

终端 B 生成自己的 Nav2 参数副本，让全局静态层订阅地图服务器的 `/static_map`，再启动导航：

```bash
export LIDAR_NAV_PARAMS="$HOME/.config/lidar/nav2_saved_map.yaml"
/usr/bin/python3 - <<'PY'
import os
from pathlib import Path
import yaml
source = Path(os.environ['LIDAR_WS']) / 'src/velodyne_bringup/config/nav2_params.yaml'
target = Path(os.environ['LIDAR_NAV_PARAMS'])
params = yaml.safe_load(source.read_text())
params['global_costmap']['global_costmap']['ros__parameters']['static_layer']['map_topic'] = '/static_map'
target.parent.mkdir(parents=True, exist_ok=True)
target.write_text(yaml.safe_dump(params, sort_keys=False))
PY
ros2 launch velodyne_bringup nav2_navigation.launch.py \
  map:="$LIDAR_WS/maps/rtabmap_nav2_latest.yaml" \
  params_file:="$LIDAR_NAV_PARAMS"
```

现有 `rtabmap_nav_complete.launch.py` / `rtabmap_localization.launch.py` 仍保留兼容入口，但定位数据库固定读取 `~/arm_car/lidar/maps/latest/rtabmap.db`；只传 `map:=...` 不会改变这个数据库路径。上面的分终端方式通过已有参数显式选择数据库与栅格，不要求将项目放回旧目录。

## 4. 语义地图包与物体导航

### 准备完整地图包

导航入口固定读取 `<maps_root>/latest/`，可以是目录或指向完整包的链接：

```text
maps/latest/
├── rtabmap.db
├── map.yaml
├── map.pgm
├── semantic.sqlite3
├── run_identity.json
└── map_snapshot.json
```

这些文件必须来自同一地图会话。`run_identity.json` 和 `map_snapshot.json` 的 `map_id` 要一致；快照要求 `frame_id=map` 且包含非空 `confirmed_semantic_objects`；语义库 `metadata.map_id` 必须匹配，`objects` 表中应有有效物体。`map.yaml` 的 `image` 必须为 `map.pgm`。

**当前副本没有预置地图，源码中也没有统一导出这六个文件的保存器。** 需要使用自己的完整备份，或从实际建图会话完成一致的地图导出与数据库备份。不要把几何保存脚本的三个输出文件当作完整语义地图包；建图时仍在写入的 SQLite 数据库需要一致性备份，不能任意拼接不同会话的数据或虚构身份快照。

### 启动并发送目标

完成地图准备后执行：

```bash
ros2 launch semantic_mapping semantic_navigation.launch.py \
  maps_root:="$LIDAR_WS/maps" \
  serial_no:=YOUR_D435I_SERIAL \
  imu_port:=auto \
  enable_chassis_control:=true
```

此入口会校验地图、检查底盘 IMU、生成运行副本，然后启动 D435i、雷达、底盘、定位、Nav2、语义导航和 RViz。它不启动 YOLO 建图节点，读取的是保存地图里的物体。

```bash
# 确认实际物体编号后发送；同类唯一时可只发送 bottle
ros2 topic pub --once /semantic_nav/target std_msgs/msg/String "{data: 'bottle:1'}"
ros2 topic echo /semantic_nav/status
```

源码默认：`enable_chassis_control=true`、`chassis_yaw_offset=π`、`standoff_min=0.9` m、`standoff_max=2.5` m、`navigation_timeout_s=300`。导航运行目录为 `~/.ros/semantic_navigation/runs/nav_<map_id>_<随机后缀>/`。

设 `enable_chassis_control:=false` 会禁用本启动链底盘节点的速度订阅，并拒绝结构化 `start` 请求；Nav2 和兼容目标入口仍可能生成 `/cmd_vel`，该参数不约束同一 ROS 网络中的其他执行节点。单独的 `semantic_navigator` 节点参数默认为 false，与 launch 的默认值不同。

### 只查询物体目录

先在一个终端订阅响应，再在另一个终端发送请求：

```bash
ros2 topic echo /semantic_nav/response
```

```bash
export LIDAR_QUERY='{"schema_version":1,"request_id":"manual-list-001","op":"list_objects"}'
ros2 topic pub --once /semantic_nav/request std_msgs/msg/String \
  "{data: '$LIDAR_QUERY'}"
```

重复使用时更换 `request_id`。路径预检使用结构化 `preview_navigation`；接口还要求实际地图与会话身份，见[协议说明](语义导航数据流架构.md#4-自然语言与任务协议)。可通过 ROSA 客户端完成身份获取、预检和取消。

## 5. 附加语义建图与独立检测

### 附加到已经运行的几何建图 / 定位链

`semantic_mapping.launch.py` 默认不启动 RTAB-Map，要求显式指定 `map_id`；没有单独的 `model_path` launch 参数，需要通过 `params_file` 设置。先生成本机参数副本：

```bash
export LIDAR_SEMANTIC_PARAMS="$HOME/.config/lidar/semantic_mapping.yaml"
/usr/bin/python3 - <<'PY'
import os
from pathlib import Path
import yaml
root = Path(os.environ['LIDAR_WS'])
params = yaml.safe_load((root / 'src/semantic_mapping/config/params.yaml').read_text())
params['semantic_mapping']['ros__parameters']['model_path'] = str(root / 'yolov8_d435i/models/yolov8n_256.onnx')
target = Path(os.environ['LIDAR_SEMANTIC_PARAMS'])
target.parent.mkdir(parents=True, exist_ok=True)
target.write_text(yaml.safe_dump(params, sort_keys=False))
PY
export PYTHONPATH="$LIDAR_AI_SITE${PYTHONPATH:+:$PYTHONPATH}"
ros2 launch semantic_mapping semantic_mapping.launch.py \
  map_id:=YOUR_EXISTING_MAP_ID \
  params_file:="$LIDAR_SEMANTIC_PARAMS" \
  overwrite_databases:=false
```

现有几何链需提供完整 TF。若相机或相机安装 TF 已由其他入口启动，分别加 `start_camera:=false` 或 `publish_camera_mount_tf:=false`，避免重复。

可选 `start_rtabmap:=true` 时还必须设置 `rtabmap_database_path` 和 `rtabmap_mode`；该组合会包含传统可控底盘入口。它与 one_click 的默认覆盖行为不同：`semantic_mapping.launch.py` 的 `overwrite_databases` 默认为 true，示例显式关闭；具体数据库复用规则见源码 `database_lifecycle.py`。

### 独立 RealSense 检测实验

独立程序还依赖 Torch、Ultralytics、OpenCV 和 RealSense Python SDK，不只依赖 `requirements.txt` 中的 ONNX Runtime；并使用 Ultralytics 的特定 `ONNXBackend` 接口。仓库没有锁定完整兼容版本，需在单独实验环境中准备，不能据此认为新环境已验证可运行。

准备好兼容的独立实验环境后，从仓库根目录执行；下面的环境目录示例应指向你已经配置好的解释器：

```bash
export LIDAR_DEMO_ENV="$HOME/.venvs/lidar-yolo-demo"
"$LIDAR_DEMO_ENV/bin/python" yolov8_d435i/detect_realsense.py \
  --serial YOUR_D435I_SERIAL \
  --model "$LIDAR_WS/yolov8_d435i/models/yolov8n_256.onnx" \
  --headless
```

此例要求所选解释器已额外安装该实验程序需要的依赖。输出为相机光学坐标系中的位置，不写入 ROS 语义地图；默认相机帧率为 60 FPS，与 ROS 主链的 30 FPS 不同。

## 6. 自然语言接口（可选外部项目）

本仓库包含语义协议服务端，ROSA 客户端位于独立项目，需要另外安装其依赖与 `.venv-ros2`。客户端和导航节点必须使用同一 ROS 网络 / domain。

先加载本工作区，再指定实际 ROSA 目录。以下方式避免现有 ROSA 包装脚本固定加载旧的相邻 `lidar/install`：

```bash
export LIDAR_ROSA_ROOT="/path/to/ROSA"
export PYTHONPATH="$LIDAR_ROSA_ROOT/rosa-ros2/src${PYTHONPATH:+:$PYTHONPATH}"
"$LIDAR_ROSA_ROOT/.venv-ros2/bin/python" -m rosa_semantic --objects
"$LIDAR_ROSA_ROOT/.venv-ros2/bin/python" -m rosa_semantic --status
```

`--objects` 和 `--status` 不初始化 LLM。真实自然语言请求通过环境变量 `DEEPSEEK_API_KEY` 注入自己的凭据，模型选择通过 `DEEPSEEK_MODEL` 与外部 ROSA 配置确定。

```bash
# 只询问物体位置
"$LIDAR_ROSA_ROOT/.venv-ros2/bin/python" -m rosa_semantic \
  --once '最近的瓶子在哪里？'

# 路径预检
"$LIDAR_ROSA_ROOT/.venv-ros2/bin/python" -m rosa_semantic \
  --once '能否靠近最近的瓶子？'

# 明确行动请求；服务端允许控制时会尝试执行
"$LIDAR_ROSA_ROOT/.venv-ros2/bin/python" -m rosa_semantic \
  --once '请导航到最近的瓶子'

# 交互模式
"$LIDAR_ROSA_ROOT/.venv-ros2/bin/python" -m rosa_semantic
```

交互中的 `/stop`、`停止`、`取消`与 Ctrl+C 直接请求取消，不经过模型。ROSA 注册五个工具：上下文、预检、导航、状态、取消；查询和预检不创建导航执行任务。旧 `--enable-navigation` 参数只作兼容，不决定服务端权限。

## 7. 标定与辅助工具

### OA-LICalib

标定与在线导航使用不同时间模式，先按 [OA 说明](../tool/oa_calibration/README.md)准备 STM32 联合授时固件、接线和雷达 PPS / GPRMC。构建环境与转换虚拟环境已清理，需要先重建：

```bash
./tool/build_oa_licalib.sh
/usr/bin/python3 -m venv tool/oa_licalib_venv
./tool/oa_licalib_venv/bin/python -m pip install rosbags python-lzf
```

构建依赖 Docker，脚本会构建 `oa-licalib:noetic` 镜像及独立 ROS 1 工作区；宿主采集仍使用 ROS 2 Humble。宿主结果分析还需 NumPy、SciPy、Matplotlib 和 PyYAML。

```bash
# 采集：按提示静止初始化，再做充分运动，Ctrl+C 保存
./tool/oa_calibration/run.sh

# 离线求解：替换为启动时打印的本轮绝对目录
./tool/oa_calibration/calibrate.sh /absolute/path/to/oa_capture_round
```

数据写入 `tool/runs/`，离线结果写入新 `output/` 目录；结果不会自动更新导航 TF。旧说明中的“本机已编译”不适用于本次清理后的副本。

### GRIL-Calib 与 IMU 内参

```bash
# GRIL：先准备其 ROS 2 / C++ 依赖，再重建和启动
./tool/gril_calibration/build.sh
./tool/gril_calibration/run.sh

# IMU：在独立且满足 ImuCalibration 依赖的环境中查看命令

```

GRIL 使用平面运动 / 地面约束，硬件采集方式见源码与[算法说明](../tool/GRIL-Calib/README.md)。IMU 采集要求对应的 STM32 串口协议和充分静止姿态，完整步骤见 [IMU 说明](../ImuCalibration/README.md)；其依赖版本和 ROS 环境分开准备。

## 8. 运行检查与常见问题

```bash
ros2 node list
ros2 topic hz /velodyne_points
ros2 topic hz /velodyne_points/deskewed
ros2 topic hz /imu/data
ros2 topic hz /odom
ros2 run tf2_ros tf2_echo map base_link
```

| 现象 | 首先检查 |
|---|---|
